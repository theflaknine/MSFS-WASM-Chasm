# WASM Chasm

> **Not affiliated with Microsoft, Asobo Studio or any aircraft developer.**
>
> **By default WASM Chasm removes only the compiled files the sim generated, and keeps the `work` folder.**
>
> **Warning: clearing an aircraft's `work` folder is a separate, stronger option. It erases that aircraft's
> own settings and saved state, and anything add-on tools stored there — for example installed navdata, a
> SimBrief alias, a Hoppie ID, or licence and activation files.** You may need to re-enter, reinstall or
> reactivate them. Everything goes to the Recycle Bin by default so you can restore it.

WASM Chasm is a free, open-source Windows utility for **Microsoft Flight Simulator 2024** on PC (Steam or
Microsoft Store / PC Game Pass). Pick one or more aircraft and remove their WASM data in a few keystrokes,
instead of hunting through AppData by package ID.

It looks like an anonymous late-1970s office terminal: amber phosphor, scanlines, and a chasm on the right
that the aircraft you clear fall into — one row at a time, as each folder actually completes.

No installer. No telemetry. No network access. No admin rights.

## Where WASM data lives

| Install | WASM root | Package data |
| --- | --- | --- |
| Steam | `%APPDATA%\Microsoft Flight Simulator 2024\WASM` | `MSFS2024\<package>\` |
| Microsoft Store / PC Game Pass | `%LOCALAPPDATA%\Packages\Microsoft.Limitless_8wekyb3d8bbwe\LocalState\WASM` | `MSFS2024\<package>\` |

A package folder holds two different things:

| Contents | What it is | Scope that removes it |
| --- | --- | --- |
| `m<hash>_<n>.{cache,dll,lib,natvis,obj,pdb}` | Generated by the sim when it compiles the aircraft's modules | Compiled cache (default), whole package |
| `work\` | The add-on's own persistent data | Work folder, whole package |

An install only counts if `UserCfg.opt` is there too. A WASM folder on its own proves nothing: on a
Store-only machine, a folder holding only licence files has been seen at the Steam path. To look at a folder
like that, browse to it (F2) or use `--root`.

2020-format aircraft use an `MSFS2020` sibling folder. Other siblings (for example `MSFS2024_now_valid`)
are shown under their own name but are **never cleared automatically** — you have to include them
explicitly on the confirm screen.

All of these paths live in [`data/locations.json`](data/locations.json). If a Sim Update moves them, edit
that file (a copy placed beside `WasmChasm.exe` overrides the built-in one).

## Using it

| Key | Action |
| --- | --- |
| ↑ ↓ | Move the cursor |
| Space / click | Mark or unmark an aircraft |
| Ctrl+A / Ctrl+D | Mark all shown / unmark all |
| `/` or Ctrl+F | Filter by name |
| F6 / Shift+F6 | Sort by name, size or date / reverse |
| Enter | Clear marked aircraft (a confirm screen always follows) |
| Esc | Cancel / clear marks / stop after the current folder |
| F1 | Help |
| F2 | Switch install (Steam / Store) or browse for a WASM folder |
| F3 | Settings |
| F5 | Rescan |

**Settings (F3):** CRT effects on/off, sound on/off (off by default), disposal method (Recycle Bin —
default; zip backup then Recycle Bin; permanent delete), backup folder, scope (compiled cache only — default;
work folder only; or whole package folder) and dry run.

More than five aircraft at once requires typing `Y` to confirm.

Aircraft are listed by the title in their `manifest.json`. If it can't be found, for example because an add-on
manager has unlinked the aircraft or the sim streams it, the list shows the package ID instead.

### Safety

- Every target path is canonicalised and must sit inside the detected WASM root (at least two levels
  down), and no ancestor between the root and the target may be a link. Anything else is refused.
- Symlinks and junctions are never followed: if a `work` folder is a link (Addons Linker and similar),
  only the link is removed and the result says so.
- The sim (`FlightSimulator2024.exe`) is checked before the run and before **every** folder. If it starts
  mid-run, the rest are skipped.
- A locked or access-denied folder is skipped and reported; there are no retries and no elevation.
- If the Recycle Bin is disabled or too small, you're asked: zip a backup first and then delete, or cancel.
  Nothing is ever silently deleted permanently. The check uses the drive the data is really on, even when a
  moved Store install reaches it through a junction.
- Each session is appended to `%LOCALAPPDATA%\WasmChasm\wasmchasm.log`. Settings are kept beside it in
  `settings.json`.

### Command line

`wasmchasm-cli.exe` is a thin wrapper over the same core, for support diagnostics:

```
wasmchasm stores
wasmchasm scan [--store steam|store] [--root <WASM folder>] [--json]
wasmchasm clear <package-id>... [--dry-run] [--scope compiled|work|package] [--include-unknown]
                [--mode recycle|zip|permanent] [--backup <folder>] [--yes]
```

`clear` is always a dry run unless `--yes` is given. The default scope is `compiled`.

## Building

Requires the .NET 8 SDK.

```
dotnet test tests/WasmChasm.Tests
dotnet publish src/WasmChasm.App -c Release -r win-x64 -o artifacts/app
```

The WPF app only runs on Windows; Core, CLI and tests build and run anywhere.

One test uses the real Recycle Bin, so it only runs if you set `WASMCHASM_RECYCLE_TEST` to a scratch folder,
ideally on another drive. It leaves a few small files in the bin.

The curvature/scanline pixel shader (`src/WasmChasm.App/Shaders/crt.fx`) is compiled with `fxc.exe` from
the Windows SDK:

```
fxc /nologo /T ps_2_0 /E main /Fo src\WasmChasm.App\Shaders\crt.ps src\WasmChasm.App\Shaders\crt.fx
```

CI does this automatically. Without `crt.ps` the app falls back to overlay scanlines and vignette (no
curvature).

## Status

Milestone **M0 (path verification with ProcMon on real Steam and Store installs) has not been done yet.**
The paths in `locations.json` are marked `"verified": false`. Until M0 is done, use dry run first (F3 → Dry
run, or `wasmchasm clear … --dry-run`) and check the listed folders.

**Seen so far, on one Store install (read-only inspection, not ProcMon):** the Store WASM root and
`UserCfg.opt` are where `locations.json` says; compiled files sit beside `work`; no `work\wasm` folder exists
in any of its 43 packages under the WASM root, despite some guides; there was no `MSFS2024_now_valid`.

**Not yet tested:**

- That the sim rebuilds removed compiled files cleanly, and that clearing them fixes the problems users report.
  The compiled-cache default relies on this.
- Anything on a real Steam install, including whether `UserCfg.opt` is at the expected path. If it isn't, a
  Steam install won't be detected and you'll need to browse to its WASM folder.
- What `MSFS2024_now_valid` is for.
